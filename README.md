## 💡 О проекте

**News Parser** — CLI-приложение на Python для сбора, обработки и сохранения новостей с веб-сайтов.

Приложение загружает HTML-страницу, извлекает информацию о публикациях, фильтрует результаты по заданному ключевому слову и отображает их в удобной таблице терминала.

Для дальнейшей работы с данными предусмотрен экспорт в два формата:

- **CSV** — для просмотра и анализа данных в табличных редакторах.
- **JSON** — для программной обработки и интеграции с другими приложениями.

Проект использует классический Python-стек без тяжёлых фреймворков. Основное внимание уделено обработке сетевых ошибок, организации кода, логированию и удобству работы в терминале.

## ✨ Возможности

### 🔍 Сбор новостей

- Получение HTML-страниц через `requests`.
- Настраиваемый HTTP-заголовок `User-Agent`.
- Установка таймаута для запросов.
- Извлечение заголовков публикаций.
- Получение ссылок на оригинальные материалы.
- Извлечение дат и кратких описаний.
- Преобразование относительных ссылок в абсолютные через `urljoin`.
- Ограничение количества обрабатываемых публикаций.

### 🎯 Фильтрация

- Поиск публикаций по ключевому слову.
- Регистронезависимое сравнение.
- Поиск по заголовку и описанию.
- Отбор только подходящих результатов.

### 🎨 Консольный интерфейс

Для оформления терминала используется библиотека `Rich`:

- Цветные информационные сообщения.
- Таблицы с результатами парсинга.
- Панели с дополнительной информацией.
- Отображение статусов выполнения.
- Итоговая статистика обработки.

### 💾 Экспорт данных

**CSV:**
- Кодировка `UTF-8-SIG` для корректного отображения кириллицы в Excel.
- Отдельные поля для заголовка, ссылки, даты и описания.

**JSON:**
- Форматирование с отступами через `indent=2`.
- Сохранение кириллицы через `ensure_ascii=False`.
- Структурированное представление новостей.

### 📝 Логирование

- Запись событий в `parser.log`.
- Использование уровней `INFO`, `WARNING` и `ERROR`.
- Фиксация сетевых ошибок и проблем при обработке данных.
- Возможность анализа ошибок после завершения работы.

## 🚀 Установка и запуск

### 1. Клонирование репозитория

```bash
git clone https://github.com/stepanwillfil-blip/news-parser.git

cd news-parser
```

### 2. Создание виртуального окружения

**Windows:**

```bash
python -m venv venv

venv\Scripts\activate
```

**Linux / macOS:**

```bash
python3 -m venv venv

source venv/bin/activate
```

### 3. Установка зависимостей

```bash
python -m pip install -r requirements.txt
```

### 4. Запуск приложения

```bash
python main.py
```

После запуска приложение выполнит сбор и обработку новостей в соответствии с заданной конфигурацией.

## ⚙️ Конфигурация

Основные настройки находятся в начале `main.py`.

Пример используемых параметров:

```python
URL = "https://habr.com/ru/news/"

SELECTORS = {
    "item": "article.tm-articles-list__item",
    "title": "a.tm-title__link",
    "link": "a.tm-title__link",
    "date": "time",
    "description": "div.tm-article-snippet__lead",
}

KEYWORD = "технологии"

MAX_ITEMS = 30
TIMEOUT = 10
DELAY_BETWEEN_REQUESTS = 1

OUTPUT_DIR = "output"
LOG_FILE = "parser.log"
```

| Параметр | Описание |
|---|---|
| `URL` | Адрес страницы для парсинга |
| `SELECTORS` | CSS-селекторы HTML-элементов |
| `KEYWORD` | Ключевое слово для фильтрации |
| `MAX_ITEMS` | Максимальное количество обрабатываемых новостей |
| `TIMEOUT` | Таймаут HTTP-запроса |
| `DELAY_BETWEEN_REQUESTS` | Интервал между запросами |
| `OUTPUT_DIR` | Директория для сохранения файлов |
| `LOG_FILE` | Путь к журналу событий |

### Адаптация под другой сайт

Для подключения нового источника необходимо:

1. Изменить значение `URL`.
2. Изучить HTML-структуру целевого сайта.
3. Определить CSS-селекторы карточек публикаций.
4. Настроить селекторы заголовка, ссылки, даты и описания.
5. Проверить корректность извлекаемых данных.

**Обрати внимание:** CSS-селекторы зависят от структуры конкретного сайта. При изменении его вёрстки настройки могут потребовать обновления.

## ⚙️ Архитектура и логика

### Обработка HTML

Для извлечения данных используется связка BeautifulSoup и `lxml`.

Информация обрабатываемых публикаций включает:

| Поле | Описание |
|---|---|
| `title` | Заголовок новости |
| `link` | Ссылка на публикацию |
| `date` | Дата публикации |
| `description` | Краткое описание |

Относительные URL преобразуются в абсолютные посредством `urllib.parse.urljoin`.

### Фильтрация новостей

После извлечения информации выполняется проверка заголовков и описаний на наличие заданного ключевого слова.

Сравнение выполняется без учёта регистра. В итоговую выборку попадают только публикации, соответствующие условию поиска.

### Сохранение результатов

Для экспорта используются стандартные модули Python:

- `csv` — формирование таблиц с данными.
- `json` — сериализация новостей в JSON.

Названия файлов формируются с временной меткой, чтобы сохранять результаты разных запусков отдельно.

### Логирование

Встроенный модуль `logging` используется для отслеживания основных событий приложения и регистрации возникающих ошибок.

Журнал сохраняется в `parser.log`.

## 🛡 Обработка ошибок

При работе с внешними сайтами могут возникать сетевые ошибки, проблемы с HTML-структурой и файловой системой.

Парсер предусматривает обработку следующих ситуаций:

| Ошибка | Обработка |
|---|---|
| `Timeout` | Обработка превышения времени ожидания |
| `ConnectionError` | Обработка проблем с подключением |
| `RequestException` | Обработка ошибок HTTP-запросов |
| HTTP-статус, отличный от успешного | Предупреждение в журнале |
| Отсутствие карточек | Предупреждение о пустом результате |
| Отсутствие нужного элемента | Предупреждение о проблеме с селектором |
| Ошибка сохранения | Регистрация ошибки файловой системы |

Ошибки фиксируются в журнале, а пользователю выводятся понятные сообщения.

## 🌐 Этика парсинга

При сборе информации с внешних сайтов важно учитывать правила и ограничения источника.

В проекте предусмотрены следующие настройки и принципы:

- Использование `User-Agent`.
- Ограничение количества обрабатываемых публикаций.
- Настраиваемый таймаут запросов.
- Возможность устанавливать паузы между запросами.
- Учет правил, опубликованных в `robots.txt`.
- Отсутствие ненужной нагрузки на сервер источника.

Перед использованием парсера необходимо проверить правила доступа к сайту, его условия использования и допустимость автоматизированного сбора информации.

Для публикации проекта:

1. Создай публичный репозиторий `news-parser`.
2. Добавь исходный код и `requirements.txt`.
